## 1. Правило роста

1. Агенты 1..3 — один столбец агентов справа, родитель 60%.
2. Агент 4 — правая зона становится двумя колонками (2+2), родитель 40%.
3. Агент 5 — секция под родителем: 1 панель.
4. Агент 6 — секция под родителем: 2 панели в ряд.
5. Агент 7 — правая зона: колонка 2 строки + колонка 3 строки.
6. Агент 8 — правая зона: две колонки по 3 строки.

Секция под родителем растёт до 2 панелей, далее рост уходит в правые колонки. После создания или закрытия панели схема пересобирается по текущему числу панелей; сохранившиеся агенты могут сменить ячейки.

## 4. Алгоритм построения layout-строки

Вход: `W`, `H` окна; `ids` — pane id окна в порядке `list-panes`.

Дерево (узел `h` = колонки рядом, узел `v` = строки друг под другом):

```
agents = N - 1
under  = 0                    если agents <= 4
         1                    если agents == 5
         2                    если agents in 6..8
right  = agents - under
pw     = round(W * 0.60)      если agents <= 3   иначе round(W * 0.40)
lh     = [H]                  если under == 0    иначе [round(H * 0.79), H - round(H * 0.79) - 1]
левая колонка = лист                              если under == 0
              = v(лист родителя, секция снизу)    иначе
секция        = лист                              если under == 1
              = h(under листьев, равные ширины)   иначе
правая зона   = лист                              если right == 1
              = v(right листьев, равные высоты)   если right in 2..3
              = h( v(a листьев), v(b листьев) )   иначе, a = right // 2, b = right - a
корень        = h(левая колонка, правая зона, [pw, W - pw - 1])
```

Строка контейнера: `WxH,X,Y{дети}` для `h`, `WxH,X,Y[дети]` для `v`. Строка листа: `WxH,X,Y,id`.
Префикс `WxH,X,Y` у контейнера обязателен (см. п.5.1).
Итог: `"<checksum:04x>," + строка`, checksum:

```
c = 0
для каждого символа ch строки без checksum:
    c = (c >> 1) | ((c & 1) << 15)
    c = (c + ord(ch)) & 0xFFFF
```

## 4.1 Расчёт размеров долями

Вход: текущие `W`, `H` окна. Доли фиксированы, абсолютные числа не хранятся.

| величина | доля |
|---|---|
| ширина левой колонки (родитель) | 0.60 при агентах <= 3; 0.40 при агентах >= 4 |
| высота родителя внутри левой колонки | 0.79 (остаток после границы — секция снизу) при агентах >= 5; вся высота при агентах <= 4 |
| панели секции под родителем | равные доли ширины левой колонки |
| колонки правой зоны | равные доли ширины правой зоны |
| строки внутри колонки | равные доли высоты окна |

Целые — метод наибольших остатков: разделить доступное пространство без бордеров, дробные остатки раздать первым ячейкам. Один вход -> один выход, результат повторяем.

Проход `select-layout` один. Систематический сдвиг psmux (первой ячейке минус 1..2) не компенсируется: ячейки одной группы могут отличаться на 1–2 колонки и на 1–3 строки (пример: 14/14/17 вместо 15/15/15 при трёх равных строках в 47 строках).

## 4.2 Поведение при изменении размера окна

psmux масштабирует уже применённую раскладку при `resize-window` без нового вызова; таблица ниже — исторический замер другой ручной сборки 9 панелей, не гарантированные значения текущего генератора:

| окно | родитель | колонки агентов | под родителем |
|---|---|---|---|
| 165x47 | 65x37 | 49x15 | 32x9 |
| 140x42 | 55x33 | 41–42x13 | 27x8 |
| 120x36 | 47x28 | 35–36x11 | 23x7 |
| 100x30 | 39x23 | 29–30x9 | 19x6 |
| 200x50 | 79x40 | 59–60x16 | 39x9 |
| снова 165x47 | 65x37 | 49x15 | 32x9 |

Следствие: при узком окне доли уводят ячейку агента ниже порога читаемости (23 колонки при 120x36). Хуков на resize в psmux нет (`show-hooks -g` пуст), восстановление инвариантов после resize требует переприменения раскладки вручную (цикл опроса расширения).

## 4.3 Обратный ход и повторный рост

- После закрытия панели: вычислить схему по текущему числу панелей; оставить родителя первым; остальные назначить по актуальному порядку `list-panes`.
- Несколько закрытий подряд: сбросить таймер предыдущей перестройки; через 120 мс применить одну схему по итоговому числу панелей.
- После повторного открытия: применить схему по новому числу панелей; прежние координаты агентов не сохранять.
- Адрес родителя: `session:window.pane` при работе с другой сессией; `%N` допустим только в текущей сессии psmux.
- Одна панель: custom-схема не строится; оставшаяся родительская панель занимает окно.
- N > 9: применять `tiled`; переход N > 9 -> N <= 9 восстанавливает custom-схему.
- Проверенный переход: 9 -> 5 -> 7 -> 1; закрытие не только последней панели. Тест: `test/integration/pane-layout-shrink.test.ts`.

## 5. Ловушки psmux 3.3.8 (проверено)

1. Контейнер без префикса `WxH,X,Y` — `select-layout` возвращает rc=0 и ничего не делает. Молчаливый отказ.
2. Явные размеры сдвигаются: первому элементу минус 1 строка/колонка, соседям плюс. Ровные ячейки требуют запроса с запасом (+1 у первых). Проверять факт через `list-panes`.
3. Ячейки назначаются по порядку списка панелей psmux (индекс 0, затем новые раньше старых), id внутри строки ячейку не выбирают. Новый агент всегда встаёт в первую ячейку схемы. Перестановка — только `swap-pane`.
4. pane id уникален внутри сессии, не в сервере: первая панель каждой сессии = `%2`, далее общий счётчик сервера. Адресация только `session:window.pane`; `list-panes -a` не различает одноимённые id — листинг только с `-t <session>`.
5. Ввод в свежую панель теряет первый байт (`echo` -> `cho: command not found`). Обход: 3 ведущих пробела + пауза после создания + отдельный `send-keys Enter`.
6. `split-window` при панели уже 21 колонки падает молча и возвращает id цели. Проверять, что вернувшийся id новый и живой.
7. Контейнер с единственным потомком (`[leaf]`) при двух панелях приводит к уничтожению окна при закрытии листа. Для одной панели агента справа использовать лист без промежуточного контейнера.

## 6. Открытые вопросы

- панелей 10: custom-схема не определена; fallback `tiled` действует до возврата к 9. Отдельная custom-схема может быть добавлена позднее.
- лестница деградации не определена: пороги (мин. ширина ячейки агента 44, мин. высота 11) и порядок понижения уровня схемы (3 колонки -> 2 -> именованный `tiled`) при узком окне.
- компенсация сдвига psmux не делается (решение): ячейки внутри группы могут отличаться на 1–2 колонки и 1–3 строки.
